# Warehouse Designer drawing output

Create Layout uses the current Warehouse Designer Parts List and its existing rack/ground assignments. It does not introduce a separate demand formula.

1. Select Greenfeild and the wall-storage permission, then upload the warehouse DWG.
2. Click Create Layout. AutoCAD must be installed and the latest local LogEn helper running. A contextual download is offered if the helper is unavailable; it is also available under CAD connection inside the editor.
3. Select the actual closed straight 2D warehouse outline and drawing units. Classify layers or individual objects as reference, blocked area, or door/exit. Review unreadable geometry in AutoCAD; add missing reserved areas in the editor.
4. Generate from Parts List. Rack footprints include the selected rack type’s structural allowances; allocations remain attached internally to each bay. Ground rectangles contain PN, original L × W × H, the pallet quantity assigned to that position, and stacking.
5. Inspect required, generated and unplaced positions. Partial arrangements identify affected PNs. Move a row/run by dragging or editing coordinates; save edits locally. Zoom to position makes individual labels readable.
6. Download Output data creates one ZIP containing an editable DWG and an Excel workbook for the same saved layout. The workbook includes the Parts List, ground positions, rack bays, explicit rack allocations, validation and settings. A partial export is clearly named and requires acknowledgement. Inventory, settings or drawing changes require regeneration before output can be downloaded.

The former Local AutoCAD conversion block is replaced by Download Output data in Warehouse Designer. Original drawing/PDF downloads remain separate. The layout PDF can be downloaded from the editor after CAD export.

Floor pallets rotate 90° automatically when their length plus floor clearance cannot fit a positive maximum row depth but their width plus clearance can. For 2300 × 900 mm, a 2000 mm row depth and 100 mm clearance, the adjusted depth is 1000 mm and frontage is 2400 mm. If neither orientation fits, floor validation reports an error. Depth 0 remains unrestricted. Rack orientation rules are unchanged.

Physical aisles use the full configured gangway width. Unchecked wall storage reserves a perimeter aisle; checked wall storage removes that automatic perimeter reservation. This conservative placement algorithm may leave unused space. It reports incomplete placement and access conflicts rather than claiming an optimized or certified building layout.

AutoCAD works on a temporary copy and adds editable LINE/LWPOLYLINE/TEXT entities on separate LOGEN layers. Original entities are preserved. Generated entities carry stable LOGEN_LAYOUT XData IDs, so re-export removes only previously generated tagged entities. PDFs plot model-space extents to A3 landscape. The browser preview simplifies geometry; unreadable objects and unresolved external references require review. The reader supports straight closed polylines as boundaries, not arbitrary CAD topology.

The helper, drawing and layout remain local to the PC/browser. Export copies before clearing browser data or changing PCs. Project JSON backups do not contain DWG, PDF or generated-layout attachments.

## Orientation optimizer

Warehouse Designer now saves Warehouse Orientation (Automatic by default), Rack back-to-back separation (0 mm by default), and Wall clearance (0 mm by default) per project. Existing physical gangway and obstacle-clearance values remain authoritative. The drawing editor lets the user approve individual wall edges for single wall rows.

The optimizer generates both horizontal and vertical arrangements in a consistent building frame derived from the dominant straight boundary direction. For each orientation it searches four starting corners, two row lengths and two depth offsets. Runs respect each rack type’s maximum run length. Interior rows are paired with configured separation and outward-facing access; singles are tried when complete pairs cannot fit. Shared aisles and perimeter routes are merged geometrically rather than counted for each row. Both candidates remain available for preview, save and DWG/PDF export, including partial candidates that pass geometry checks.

Ranking rejects geometry/access violations, then compares accommodated required pallets, full coverage, unusable area, circulation area and block count. Area calculations use offline Clipper polygon boolean operations and offsets at 0.1 mm precision, including concave boundaries, clipped obstacles and holes. Unused components are classified using a bounded search for configured footprint fits. Narrow tails within an otherwise usable component may remain classified as potentially usable. This is a bounded heuristic, not proof of a global optimum.

The comparison reports warehouse/available/storage/gangway/clearance/free areas, pallet quantities, bay counts, utilization, complete placement and separate geometry/access and safety statuses. Fire and safety information not present in the drawing is unverified. The user must confirm required constraints; unreadable drawing entities retain an unverified status. Blocks and unsupported geometry use conservative bounds or require review. Automatic door, wall and fire-equipment semantics are not inferred.

The version 4 local helper writes editable rotated polygons on LOGEN_RACKS, LOGEN_GROUND_STORAGE, LOGEN_GANGWAYS, LOGEN_CLEARANCES and LOGEN_LAYOUT_LABELS, preserving the original drawing and replacing only tagged generated entities. Output Excel includes the selected scenario and comparison metrics. Inventory, demand, stacking and rack shelf-allocation formulas are unchanged.

Focused verification: `node webapp/layout-optimizer.test.cjs` covers paired racks, allocation identities, non-overlapping area partitions, rotated buildings, approved wall rows, shortages and a concave boundary. AutoCAD export is also checked with a synthetic warehouse drawing.

## Ground separators and shortage alert

Ground row borders and separators between occupied positions are green in the browser, DWG and PDF. Markings use the existing clearance space, merge shared collinear edges, and do not change footprints or pallet quantities. AutoCAD helper version 5 writes these editable lines on LOGEN_GROUND_MARKINGS.

After generation, on opening a saved partial layout, and when selecting an incomplete orientation, a shortage window shows unique affected PNs, unplaced pallet quantity and allocated storage-only area still needed. The report lists every affected PN. Shared missing rack bays count once, with their area apportioned across assigned PNs. Dedicated ground rows retain the existing row-depth reservations, clearance and stacking. Additional gangways are excluded because an extra physical aisle layout has not been generated. Unknown quantities or areas are explicitly flagged rather than treated as zero. The same data is included in the Excel output's Storage Shortage sheet.

## Wall-first placement correction

With Allowed storing on the wall enabled, the first rack row is anchored to a clear boundary wall with only the configured wall clearance. If no wall is selected, the optimizer tries a boundary wall automatically; selecting a specific wall restricts that choice. Doors and blocked areas still prevent placement. The cross aisle begins after the wall-row depth, so it no longer leaves a hidden end-aisle strip beside that row. The next interior rack block starts after exactly one configured gangway. With wall storage disabled, perimeter gangway behavior is unchanged. Regenerate older layouts to apply this correction.


Ground-layout search performance: fixed placed-group rectangles/access strips are reused; rejected non-wall ground poses are reused within a candidate while occupied storage grows. Rectangular region checks use the same 0.1 mm coordinate grid and area tolerance as the polygon engine; concave shapes, holes and negative-size rectangles retain polygon clipping. Source rows are reused in validation/shortage accounting. Wall ground rows keep their successful wall pose and their individual pallet coordinates. Search still compares both orientations, retains imported stacking, validates access and reports all unplaced inventory.


Interior ground storage uses continuous lanes with one straight shared center line. Dedicated PN rows fill the frontage on both sides before another lane is opened; small residual gaps that cannot fit the remaining pallet frontages stay empty. Within each PN row, pallets are placed outward from the center line. Maximum floor row depth applies independently to each side; zero remains unrestricted except for actual physical space. The normal floor footprint clearance is split equally at the shared line: 100 mm gives 50 mm from each nearest pallet, without another center gap. The first/last loading faces and lane ends keep full physical gangways. Obstacles can divide a lane into separate accessible segments. Single rows stay at approved walls. Stock and the floor stacking mode selected in Overview are unchanged, every position keeps a stable ID, and all unplaced stock is reported. A lone position leaves the other side empty instead of creating inventory. The CAD export includes one continuous center marking; 3D uses the same saved positions and center line. Regenerate older layouts to apply this arrangement.


Stacking controls are in Overview below Shifts & days on hand. The selected manual / height-limit / imported mode is used by both footprint calculations and Warehouse Designer; there is no all-ground override. Maximum floor stacking height caps ground stacks. Building height is a separate positive setting used to check levels × (usable shelf height + structural height allowance). New rack allocation excludes types whose complete frame exceeds Building height, while installed infrastructure remains visible and flagged. Older saved projects initialize Building height from their previous Maximum floor stacking height to preserve the prior height limit; the two fields are independent afterward.

Ground line compaction joins collinear ground sections when their depth bands overlap, including sections with different pallet depths and offset center lines. Both faces are packed consecutively using the existing floor clearance, without a separate run-end gangway in the middle. Approved wall rows are also joined where clear. All position IDs, quantities, dimensions, floor stacking and PN row assignments are preserved. A join must pass the same boundary, obstacle, door/main-route and outer-gangway checks as a new placement. Regenerate older layouts to apply optimizer version17. The synthetic regression includes both orientations, all four walls, retained blocked/route gaps and exact3D inventory.

Optional ground rotation: Warehouse settings > Floor storage & gangways > Allow 90° rotation for better ground storage fit. Disabled by default; the existing necessary row-depth fallback is retained. When enabled, footprint calculations compare both orientations by allocated footprint, and physical lane packing compares row frontage and attempts a turned row in a residual frontage gap. Stacking, stock quantity and clearance are unchanged. Saved/exported settings include groundAllowRotation. Optimizer18 requires regenerate/save for current 3D geometry. Empty space at the end of the final lane can simply be surplus capacity when all inventory is placed; it is not filled with fictitious stock.

All-around ground wall storage reserves a square at each warehouse corner with side length Maximum floor row depth. Both ends of every wall row start/end outside that square, independent of wall order or warehouse orientation; interior storage and manual moves must also avoid it. The reserved corners are included in clearance/access area accounting. For depth0/unrestricted, the actual deepest wall-row reservation is used as a finite corner size. Single-wall ground storage and rack-only wall/corner behavior are unchanged. Optimizer19 requires regenerating saved layouts. Automatic compares completed horizontal and vertical candidates and ranks valid arrangements first by accommodated pallets; progress now names the orientation being compared.

CAD ground box Stacking labels show the height-based maximum for each PN: FLOOR(Maximum floor stacking height / loaded pallet height). The drawing payload carries maximumStacking and retains effectiveStacking separately; physical layout, actual per-position quantity and selected stacking factor are not changed. Existing helpers still receive the calculated numeric maximum in the display stacking field, so no helper update is required for the new number. Drawing appearance cache3 invalidates prior DWG/PDF output only, preserving saved/manual layout coordinates. Re-export the drawing to update labels. Existing ground occupancy annotations include Maximum stacking; rack annotations remain unchanged.

Projects > Download Project Files creates one ZIP for the clicked project, without changing the active project or category filter. It contains edited Layout.dwg, Layout.pdf, Layout_List.xlsx (exact saved layout PN set/positions, including shortages), and LogEn_Results.xlsx (the complete project's Export Results calculations across all categories). An existing matching drawing/PDF cache is reused; if generation is needed it uses the existing CAD export path. A missing or stale saved layout, missing source DWG when regeneration is needed, or PDF failure is reported before any ZIP is downloaded. No requested file is silently omitted. Saved filtered layouts keep their matching PN subset for the layout list while the calculation workbook covers the whole project. Partial drawings retain Partial_Layout in their filenames.
